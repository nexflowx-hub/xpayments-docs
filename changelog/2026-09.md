# September 2026

## 2026-09-10 — Stripe-compatible Direct E2E certification

The Stripe-compatible Direct path was validated through controlled TEST and LIVE flows.

Validated capabilities include:

- Store-scoped `xp_test_*` / `xp_live_*` authentication;
- Stripe-style HTTP Basic authentication and Bearer authentication;
- PaymentIntent creation through `/api/stripe/v1/payment_intents`;
- deterministic create idempotency;
- `metadata[nexflowx_transaction_id]` finance binding;
- Stripe.js / Payment Element using the Store `pk_*` key;
- Stripe provider webhook verification by XPayments;
- XPayments Transaction finalization;
- WalletMovement creation exactly once for the validated payment flow;
- provider routing through vNext ProviderAccount / ProviderConnection / GatewayVault;
- automatic payment methods on an eligible LIVE Store.

Merchant webhook delivery remains dependent on the merchant endpoint using the current XPayments HMAC contract documented in [Merchant Webhooks](../guides/webhooks.md).

## 2026-09-10 — Merchant webhook contract clarified

The canonical merchant signing header is documented as:

```text
x-nexflowx-signature
```

with lowercase hex HMAC-SHA256 over the exact raw JSON request body using the Store webhook secret.

The webhook amount representation is documented separately from create APIs: create operations use minor units while the current normalized merchant webhook payload exposes the transaction amount in major units.
